# PROJECT RULES — Lab 03 Exercise 2

**Project:** Pioneer (Scientist) Directory — Search, Filter & Sort
**Component:** `<ScientistDirectory />` (React 19 + Vite)
**Scope:** These rules are enforced during the in-class sprint, the AI audit, and the live defense.

---

## 1. Sprint 2 Code Contract

| # | Rule | Implementation Requirement |
| :--- | :--- | :--- |
| 1 | **Single Source of Truth** | Only raw independent inputs live in `useState`: `people`, `query`, `minIq`, `sortBy`. No mirrored state. |
| 2 | **Pure Derived State (Render Cascade Rule)** | The filtered + sorted `visiblePeople` list is computed in **1 pass during render, with ZERO effect hooks** — no `.filter()` results stored in `useState + useEffect`. |
| 3 | **100% `<label>` Bindings** | Every input is bound via `<label htmlFor={id}>` with ids generated by the React 19 `useId()` hook (`queryId`, `iqId`, `sortId`). |
| 4 | **Accessible Search Landmark** | The filter bar is inside `<form role="search">`; submit is prevented (`e.preventDefault()`). |
| 5 | **Screen-Reader Live Counter** | `<output role="status" aria-live="polite">` announces "Found N pioneers" on every re-render of the derived list. |
| 6 | **Immutable Deletion & Reset** | Delete uses `setPeople(prev => prev.filter(...))` (no mutation); Reset restores `initialData` and clears every control. |
| 7 | **Type-Safe Numeric Input** | `minIq` uses `e.target.valueAsNumber` with a `Number.isNaN` guard — never a `'string' >= number` comparison. |
| 8 | **Stable Keys** | Every row uses `key={p.id}` from a stable data schema (`sp-1`…`sp-6`). |
| 9 | **Button Semantics** | All `<button>` elements declare `type="button"`; delete buttons carry a dynamic `aria-label={`Delete ${p.name}`}`. |
| 10 | **Empty State** | When `visiblePeople.length === 0` an explicit "No pioneers match your criteria." message renders. |
| 11 | **Deprecation Audit (Lab 2 rules)** | NO `var`, NO `innerHTML`, NO inline `onclick` HTML attributes. |

## 2. Anti-Hallucination Rules (AI Failure Mode Audit constraints)

1. **No Redundant `useEffect` for Derived State** — filtering/sorting must never be stored in a `useState + useEffect` pair (Top AI Failure Mode #1).
2. **No Stale Closures** — any debounced search handler or event listener needs correct `useEffect` dependencies plus a teardown (`clearTimeout` / `removeEventListener`).
3. **No Missing Cleanup** — every timer or listener is cleared/removed on unmount.
4. **No Naive Drift Timers** — countdown logic must not use plain `setSeconds(s => s - 1)` without drift compensation.
